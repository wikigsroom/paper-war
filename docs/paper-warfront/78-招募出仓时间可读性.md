# 招募出仓时间可读性

针对持续波次中补前排与完成混编竞争金币、生产时间的问题，桌面和移动招募队列现在显示每个订单的累计预计出仓时间。估算包含前序订单的生产等待，并扣除队首已经完成的生产时间；相同兵种的重复订单按索引分别计算。

提示明确写为“打开时估算”，因为查看队列时战斗继续进行。出仓不是抵达前线：行军、阻挡、控制和战线变化均未计入，界面不会将出仓时间误称为守矿援军抵达时间。计算只读取己方队列，不读取敌军或迷雾情报，不修改模拟和资源。

Windows原生Godot运行 game/tests/test_recruitment_readiness.gd，14项检查通过：双方真实付费重复招募、已消耗生产时间、累计等待、无副作用、实际生产误差不超过一个60Hz步进、取消队首及非法索引。移动队列按钮增加为64高度，以容纳两行文字。

修改尚未进入rc10 EXE/APK。原生渲染与触控布局尚待本轮验收，不能以机制测试替代截图或真机证明。本轮没有改变默认AI、价格、生产速度或地图，持续守矿与反扑缺口仍需继续处理。

## 当前选路的基础行军时间

后续开发源码加入桌面兵卡提示与手机长按资料：按当前基地出仓投影、所选分岔及实际道路折线，估算新兵以基础速度走到当前同路线最远己方存活作战兵的位置所需时间。不同分支上的兵不冒充可达前线；改道后重新计算。己方纸工不被计入战线，工人卡改为说明采矿运输职责。

这是当前位置的基础行军估算，不是预测接敌或安全抵达。界面明确排除阻挡、控制和战线变化；手机资料标记打开时估算。没有己方前线时不提供虚构时间。敌方自定义出兵入口不提供该估算，因为后续出口可能随导演时间改变。未读取敌方单位属性、数量或位置。

扩展原生测试共54项通过，包含短/中/长图双侧与实际 map.advance 行军距离对照、排除死亡单位、不改变道路选择和单位、隐藏敌军不影响估算、双侧分岔排除及切换选路。Godot完整项目无渲染启动两帧成功，无脚本错误。上述仍不是界面文字布局、Android硬件或持续反扑验收；尚未导出新程序。
