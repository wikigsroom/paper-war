# 夜战灯笼 UI 运行时落地与验收

版本：`3.0.0-rc40-night-lantern-ui`  ·  引擎：Godot 4.7.2  ·  日期：2026-10-15

本章把已选定的 03「夜战灯笼」方向落到 Godot 原生 Control UI 和纸片舞台渲染中。它只改变表现层和交互表面，不改变战斗模拟、伤害/碰撞、路线选择、战争迷雾可见性或关卡规则。

## 视觉契约

| 角色 | 运行时令牌 | 用法 |
| --- | --- | --- |
| 夜幕 | `MIDNIGHT #0d1c2e` | HUD 轨道、弹窗遮罩、背景冷色压暗 |
| 深蓝纸 | `PAPER #14283b` | 战场命令轨、路线图图例底 |
| 象牙纸 | `CARD #fff6e2` | 任务简报、科技、建造、暂停、结算面板 |
| 墨字 | `INK #1b2c40` | 象牙纸上的正文与按钮文字 |
| 夜字 | `LIGHT_INK #f3e6cc` | 深色 HUD 上的时钟和高亮文字 |
| 朱印 | `SEAL #a43b2d` | 主行动、危险、折角和敌方标记 |
| 金箔 | `GOLD #d2a24f` | 资源、完成线、焦点框和灯笼边线 |
| 玉青 | `JADE #4d9299` | 法力、己方可用目标、辅助状态 |
| 灯火 | `LANTERN #f1a34b` | 纸场基座和轨道端点的暖色光源 |

背景源图仍是现有纸片山河资产，由 `NIGHT_SCENE_MODULATE` 和冷色夜幕覆盖统一为夜景；未知区域的雾面改为深蓝墨雾。`theatre_fog.gd` 的 `current/explored` 计算、记忆状态、道路分层和透明度逻辑未改动。

## 运行时页面映射

| 页面 | 实现位置 | 夜战灯笼处理 |
| --- | --- | --- |
| 主菜单 | `game/scripts/main.gd::main_menu`、`game/scripts/battle_view.gd` | 主标题改用象牙/朱印双色，背景冷色压暗，右侧保留大面积象牙命令纸 |
| 任务简报 | `show_brief`、`map_preview.gd` | 地图预览使用深蓝纸底、金线道路、灯火矿点、玉青施工点 |
| 实时战斗 | `build_hud`、`theatre_hud.gd`、`battle_view.gd` | 顶部/底部为深蓝命令轨；资源、法力、时钟按夜字/金箔/玉青分工；战场保留 70% 以上可视面积 |
| 军令/研究/建造/暂停 | `create_overlay`、`mobile_ui.gd` | 冷色遮罩压低战场，象牙纸面板与朱印主按钮形成焦点层级 |
| 战斗结算 | `show_result` | 象牙结算纸、玉青胜利标题、金箔星级、朱印重开行动 |
| 战役路线 | `campaign_route_graph.gd` | 可行动路线用金箔，等待前置用浅夜字；路线卡和图例仍是原生可点击控件 |
| 移动端 | `mobile_ui.gd`、`paper_panel.gd` | 横屏安全区、48dp 触控目标、底部操作轨和顶部状态轨共享同一令牌；滚动与返回栈保持原有行为 |

`PaperPanel` 对 `HudTopRail`、`HudBottomRail` 等语义名称延后一帧套用 `rail_box()`，避免控件刚加入场景树时名称尚未赋值而误用普通纸卡皮肤。

## 验收证据

- Godot 编辑器无脚本解析错误：`Godot_v4.7.2-stable_win64_console.exe --headless --path game --editor --quit`。
- 场景观察器：10/10 页面捕获成功，错误计数为 0，来源为当前 Windows 导出 PCK。
- `tools/paper-warfront/check_paper_ui.py`：桌面 49 项通过、手机 49 项通过。
- `tools/paper-warfront/check_mobile_adaptation.py`：桌面/手机/高密度/刘海/反向刘海/平板/竖屏恢复全部通过；最小实机场景模型战场可视比例为 0.7061，满足 70% 约束。该结果是 Windows 原生注入触控与密度的回归，不等同于 Android 真机 FPS 证明。
- 构建脚本完成 Windows EXE 导出、Android APK 签名、zipalign、badging、manifest 和 arm64 ELF 检查。
