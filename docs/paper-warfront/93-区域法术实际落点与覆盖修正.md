# 区域法术实际落点与覆盖修正 · rc13开发中

## 当前源码更新

区域法术不再只把敌人站位当作候选中心。AI比较已知敌人的位置及可覆盖敌人对的中间点，先投影到实际可走纸面，再使用真正的区域半径计算覆盖。候选仍必须通过与玩家一样的法力、冷却、视野和地形规则。

同覆盖人数时保留原有合法落点；受伤前排权重experimental_ai_area_threat_weight默认关闭。没有敌人情报时不能使用隐藏敌人或隐藏fallback落点。重复落点去重，已覆盖全部已知目标时结束搜索。

实际施法的有用性与排序也使用该区域实际覆盖人数，修复旧的固定2单位聚类门槛：两敌之间超过2单位、却仍在同一毒园可覆盖范围内时，不应把施法当作无效。原始聚类仍服务其他技能，不将所有法术半径统一改成毒园大小。

这是所枚举合法候选中的最大覆盖，不宣称连续平面全局最优。持续区域将来如何移动、敌人进出及控制收益不是当前覆盖的保证。

当前工程版本rc13-dev，Android开发版本码30012；未导出新的EXE/APK，最近已交付仍为rc12-preview。没有改单位价格、研究费用、法力收入或道路数据。

## 首轮实际交换定位

rc12正常完整AI长图双侧观察：23.42秒毒园选在后方投矛兵附近，32.62/40.03秒两守卫死亡，44.02/49.58秒两毒种死亡。前60秒守卫承受投矛259.85、斧手255.40物理实际扣血，另有110非物理扣血。投矛与斧手共同造成压力，不能只把迟到支援作为根因。上述为实际hit事件归组，不包含所有再生恢复账，不把空来源UID的扣血强行分类为某个法术。

首次带受伤前排权重的原型延后短图失守，却使中/长图部分工人更少；因此同人数加权不进入默认策略。该原型当时代码内启用权重、未独立记录权重开关，作为历史定位保留，不用其报告证明当前默认设置。

桥面与地面的半空中点会被区域吸附到实际纸面，原型若按半空点计数会高估覆盖。当前已将投影放在计数之前；不能用合法点击点的原始位置代替实际区域位置。

## 原生机制证明

双侧28项通过：真实视野、敌人中心不能覆盖分散两敌、中间实际纸面能覆盖两敌、查询无副作用、隐藏身体/生命/fallback不影响落点。实际AI而非直接手工调用施法支付40法力，两个目标随后实际中毒扣血。

另检验纸桥岔口上下路：中间半空点投影后不能覆盖两路时，不虚报两敌；实际cast产生的spell_area中心与选择位置吻合。50敌密集压力场景仍覆盖全部目标，单次查询约0.6毫秒，只是原生CPU受控查询，不是帧率或Android性能。

## 证据

当前最终对照：output/qa/godot/core-alignment-rc13/exchange/area-emergency-comparison.json及其六个原生日志。原始交换观察：long-baseline.json。前排权重原型：area-aim-comparison.json；中间阶段：area-coverage-comparison.json、area-projected-comparison.json。各阶段保留各自来源哈希，不混作同一源码。

完整42组12786项机制回归通过，运行输入仍与当前源码一致，报告位于emergency-area-regression。此前integrated-area-regression暴露救命打断排序失败，保留失败历史，不充作通过证据。

新覆盖排序曾让毒园优先于廉价敌人的致命前摇，原因是排序仅检查最贵敌人。当前先扫描所有可见敌人的dangerous_windup，再排序法术，恢复单发致命/重击打断高于区域投入的优先级。10项施法预算检查全部通过，保留隐藏情报、锁定、长/短冷却与紧急打断边界；可被真实区域覆盖的分散两敌改为实际40法力施放断言，不能继续要求不施放；剩余法力充足且区域尚有0.5秒冷却的场景仍可付30法力控制并保留40。下一步需延长正常观察，检验短图保住经济后能否实际科技反推；150秒未决不证明长期无法获胜。同时单独定位中图矿线/控制窗口，并验证其他阵营的区域技能；原作精确规则、全阵营全地图平衡、真人操作与Android硬件均未完成。
