# 玩家视野与前线导航 · rc22

本轮继续检查上一版的雾幕与地图比例，发现自动镜头没有真正按玩家分侧。东侧玩家的「追踪交锋」仍读取西侧视野；联机客户端已经过滤了西侧的敌情，因此相同前线在服务端和客户端可能得到不同镜头中心。没有接敌时，旧算法还会使用敌方基地前方的固定位置取中点，使开局镜头移到大量未知区域。

当前正式版本为 `3.0.0-rc22-preview`，Android版本代码为 `30021`。本页配套的最终包、编译来源和核验记录见 [发布目录](../../release/3.0.0-rc22-preview/README.md)。本轮属于本作导航修复，没有新增原作录像或精确视野参数证据；[rc21原作参考和地图比例记录](130-迷雾呈现与地图比例修复及rc21交付.md)继续说明这部分边界。

| 问题 | 旧包实际表现 | 正式修复 |
|---|---|---|
| 玩家视野 | `front()`固定检查西侧视野，东侧镜头可以受到自己看不见的西侧单位移动影响 | `front(side)`只消费该玩家的当前合法情报；主视图、军令、快捷键、同屏和联机传入实际玩家侧 |
| 尚未接敌 | 使用敌城前方的固定位置取中点，镜头偏离己方部队 | 跟随己方最前面的存活作战单位；没有作战单位时回到己城前方 |
| 多路地图 | 只对可见单位的横坐标取极值，不能区分附近交锋与另一路远处目标 | 按实际道路距离寻找前线视野半径内最近的可见作战单位或建筑；附近交锋取中点，隔远路的单位不拉走镜头 |
| 作战焦点 | 工人被排除，但阵亡列表和固定初始位置仍可影响结果 | 纸工和阵亡对象均不参与前线；目标丢失后跟回己方部队 |
| 手动导航 | 同屏/联机拖动改变目标，但下一帧自动追踪又将目标覆盖 | 拖动战场或点击小地图关闭自动追踪；军令「追踪交锋」可恢复 |
| 小地图触控 | 在小地图按下后保留战场触点编号 | 小地图导航立即释放战场捕获，不干扰下一次拖动 |

模拟侧实现见 [battle_sim.gd](../../game/scripts/battle_sim.gd)，视图和输入见 [battle_view.gd](../../game/scripts/battle_view.gd)、[local_duel.gd](../../game/scripts/local_duel.gd)、[main.gd](../../game/scripts/main.gd)和[mobile_ui.gd](../../game/scripts/mobile_ui.gd)。这个查询不改视野、资源、AI、目标判定或行军速度。主机与客户端查询同一份合法视野能够得到相同镜头目标。

地图横向仍为112、纵向64逻辑像素/世界单位，纸偶倍率0.78；42世界单位地图约2.94个桌面标准视窗。普通纸偶约124逻辑像素高，地表下保留150.8逻辑像素纸层；手机普通兵至少60dp、纸工52dp，巨型兵保留约40.8%的高度差。风格参数升级为[1.2.0](../../assets/paper-warfront/style-tokens.json)，新增稳定ID `camera.common.observer_front`的分侧追踪约定，运行副本保持字节一致。地图/雾幕资源继续使用rc21修订，38项折纸UI位图仍沿用rc16的 `sub2-image-gen / gpt-image-2.5`正式素材。本轮没有新位图生成。

原生检查分为两类：

- [82项机制检查](../../game/tests/test_observer_camera.gd)：两侧的隐藏单位移动不影响镜头、平行路和相邻路段、退出视野、工人/阵亡过滤、客户端投影一致、视图分侧，以及同屏/联机的原生触控状态。同一观察器在实际rc21 EXE中复现问题，旧报告保留于[对照目录](../../output/qa/godot/observer-camera-rc22/before-final/report.json)。
- [44项原生GPU观察](../../output/qa/godot/observer-camera-rc22/release/camera-render/report.json)：桌面和注入手机显示指标各22项、各六张原生截图。使用正式地图、正常初始资源与双方真实招募付款，检查开局Space、行军、实际伤害交锋、东侧网络投影、ScreenTouch和真实军令按钮。AI在这个可重复场景中关闭；不将该场景当作完整AI或真人互战证据。旧EXE对应截图和失败记录见[对照渲染](../../output/qa/godot/observer-camera-rc22/render-before/report.json)。

首次新增GPU观察器误将特效事件名 `impact` 当作实际伤害事件 `hit`，使记录继续模拟到一方阵亡。修正的是观察器的伤害计数，正式战斗代码没有因该观察失败改动；[原始失败记录](../../output/qa/godot/observer-camera-rc22/source-render/report.json)保留。联机截图在最后观察器中执行原生面板状态刷新，避免未刷新状态栏被用作成品截图。

同一82项观察器在旧包有38项失败，在当前源码和两个实际编译包均为0项失败。GPU对照中旧包两配置各有6项失败，新包各22项全部通过。实际EXE的[己方行军前后对比](../../output/qa/godot/observer-camera-rc22/figures/own-front-before-after.png)和[开局镜头对比](../../output/qa/godot/observer-camera-rc22/figures/opening-before-after.png)均由同地图、同种子、同付费时序的原生截图合成，不是原作画面或概念图。原图和散列见[图表记录](../../output/qa/godot/observer-camera-rc22/figures/comparisons.json)。

APK逻辑观察器原先只提取脚本/数据，新增控件检查缺少字体与纹理，产生资源加载错误。现在直接从同一APK提取其导入资源；已经通过的18组仅在APK、编译字节、数据和对应观察器哈希完全相同的条件下保留，新增82项独立重跑通过。原报告和日志仍在[APK检查目录](../../output/qa/godot/observer-camera-rc22/release/apk-logic/)；没有用工作区素材或脚本替代APK内容，也没有将保留结果算作第二次执行。
