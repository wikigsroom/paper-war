# RC38 导出资源排除与包体复核

RC38 重新导出时发现 Godot 的 `all_resources` 会把工作区 `output/` 下的 QA 截图、报告和历史生成物一并纳入 PCK。它们不属于运行时资源，既增加包体，也会让发行包依赖本机验证目录。Windows 与 Android 两个预设现在都显式加入 `output/*` 排除规则；`tests/*`、文档、历史动作源图和仅供审查的素材仍按原合同排除。

运行时仍保留 `data/unit-frames.json` 的动作裁剪合同和 `assets/animation/frames-v1` 的实际图集。`unit-frames.json` 里的 `preview` 字段只记录 QA 预览地址，运行代码不读取该字段，也不需要将 `output/qa` 带入交付包。

## 交付包回归

- APK 自身提取出的 GDScript、JSON 和导入资源：38 组，195115 项，全部通过。
- Windows EXE 内嵌 PCK：38 组，195115 项，全部通过；嵌入包与 APK 的脚本和数据散列一致。
- 本次改动没有改变战斗规则、单位动作、采矿、友军伤害过滤、战争迷雾、地图长度、剧情路线或移动端布局，只收紧导出资源边界。
- Android 没有实体设备可用，因此本项仍只代表 APK 结构、字节码和 Windows 原生抽取回归，不把它表述为 Android 真机性能结论。

源码提交的导出约束见 `game/export_presets.cfg`；构建入口仍是 `tools/paper-warfront/build_game.py`。生成物和 QA 证据继续留在本地 `release/`、`output/`，不会进入 Git 源码仓库。
