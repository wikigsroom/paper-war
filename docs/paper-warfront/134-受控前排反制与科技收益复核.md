# 受控前排反制与科技收益复核 · rc25

rc25 修复正常 AI 在前排被敌方远程控制时，继续补近战、缺少有效反制的问题。采用实际观察到的束缚、眩晕、根缚和减速作为条件；已有射程足够的存活友军或付费订单时，不重复购买。研究后的首次部署目标继续保留，反制兵也必须支付原价并经过生产与行军。

本项继续使用已经核验的 [地图比例与全舞台迷雾](130-迷雾呈现与地图比例修复及rc21交付.md)、[分侧视野与导航](131-玩家视野与前线导航修复及rc22交付.md) 和 [首次研究订单](133-研究后付费部署闭环与rc24交付.md)。本次没有生成新位图；38 项折纸 UI 与独立整身动作沿用现有 `sub2-image-gen / gpt-image-2.5` 资源。

## 具体问题与正式边界

rc24 正常 300 金币、敌方等待 4 秒的印垒对木拓中，签盾兵在 64.22 秒出仓，绕桥后被木拓远程单位根缚与减速。它没有实际命中，在 127.68 秒阵亡；印垒继续花钱补近战，最终失去采矿队。更早的刀盾卫已遭木拓束缚，因此有效反制的付款窗口出现在高级兵出仓之前。

实现位于 `tactical_ai.gd` 的 `contact_ranged_offer`，只在正常规划器的公开招募流程中执行：

- 敌人必须存活、敌对、当前可见，并使用远程飞弹武器。隐藏对象、阵亡对象和转属友军不能提供反制需求。
- 本方存活前排必须已经处于该敌人的射程内，且受到敌方束缚／眩晕，或根缚／减速使它停在自身有效触及之外。普通接近过程不会触发。
- 根缚和减速仍允许已触及的近战攻击；不能把它们当成完全停火。
- 出兵口被近战占据时沿用原有紧急前排优先级。没有金币则沿用原招募决策，不把预计回款当可支付资金。
- 只能选择本院本局合法、已经解锁且允许手动招募的飞弹兵。以真实射程和真实价格选兵，不改伤害、速度、科技、地图或视野。
- 已有足够射程的存活友军，包括尚在增援路上的兵，以及相应付费订单，均阻止再次购买。这个保守规则仍可能低估分路后的独立反制需求。
- 实际购买通过原公共命令扣费；纯需求查询不消耗随机数、不支付、不生成单位，也不读取敌方金币与研究。改买反制兵不会清除已付研究的首次部署目标。

| 候选 | 实际范围 | 已确认的问题／结果 |

| R1 | 当前远程交锋、现金足够 | 印垒正常入口改善；没有限制实际受控状态 |

| R5 | R4 加存活／在途反制兵去重 | 收紧后保留正常入口改善；用于 rc25 预览，所有退化继续留档 |

R1–R5 的源码、差分、生成器摘要和观察报告保存在 `output/qa/godot/fielding-contact-rc25/`。R1/R2 原生成器、原共享状态观察器与修正后的观察器均按原摘要归档，没有改写旧报告来使其通过。

初始诊断观察器曾把状态字典引用写入历史采样，后续状态会污染旧样本；位置、生命与独立事件值未受影响。修正为深拷贝后重新观察，诊断以 `rc24-yin-mu-menu-v2` 为准。两次提前发起的汇总只因最终报告尚未生成而退出；完整矩阵结束后才生成正式比较文件。

## 程序验证与交付

`3.0.0-rc25-preview`，Android versionCode `30024`。71 组 15,634 项源码机制、两包各 27 组 2,744 项编译逻辑检查通过。新源码与冻结 R5 摘要完全相同；相对 rc24 的正式公开输入只改 AI、工程版本与导出版本，地图、价格、视野和位图摘要保持一致。

实际 EXE 编译内容的印垒／木拓正常入口在 OpenGL 桌面与注入手机指标各通过 32 项：受控刀盾卫在 59.82 秒被观察，60 金币投矛手在 61.77 秒付款、63.57 秒出仓、74.10 秒造成 14 点实际敌对伤害；签盾兵在 111.02 秒出仓，147.55 秒首次造成 10.74 点伤害。双方实际金币账差额均为零，16 张阶段截图没有单位、金币、生命、科技或位置补助。

另行执行 Windows 默认 Vulkan Forward Mobile 桌面渲染，32 项与八张图通过；默认与兼容渲染呈现均实际检查。GPU 观察结束于首次签盾兵命中，不能当作 CPU 206 秒胜利的执行证据，也不证明实时 FPS。原来的印垒镜像正常入口仍通过 50 项。
