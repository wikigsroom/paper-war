# 剧情路线图与运行绘制缓存调优

本次把“地图有剧情、路线不强制线性”继续落实到单机章节页和运行层。章节页现在直接显示 `campaign-flow.json` 的同章后继关系：已完成或当前可行动的道路使用金色，等待前置证据的道路使用灰色；跨章节连接由章节选择器承接。路线图只是可读的导航层，关卡按钮、解锁条件和存档仍由 `CampaignProgress` 的同一份节点数据驱动。

桌面章节页保留 20 张纸页卡片的可点击布局，卡片后方新增分支/汇流连线和回访图例。手机章节页继续使用滚动卡片与章节路线摘要，避免把小屏高度用于密集连线。实际 EXE 的桌面和手机故事路线观察各通过 237 项，覆盖两处分支、条件汇流、存档重载和 200 张剧情简报。

运行层增加了两个只读缓存：单位高度按设备缩放与资产 ID缓存，单位的物理投影点在单帧内复用。缓存每个模拟帧清空，不改变战斗字典、碰撞、迷雾、采矿动作、帧选择或命中顺序。缓存前后使用同一套源码战斗、迷雾和剧情合同；当前 v2 原生 124 单位压力窗口为 29.70ms/帧均值、52.38ms p95，仍明确不宣称稳定 60FPS。压力窗口在外部 Godot 导出任务结束后重新采样，受干扰的旧样本没有写入发布验证。
