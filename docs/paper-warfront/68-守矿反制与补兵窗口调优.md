# 守矿反制与补兵窗口调优

## 受控反制实测

短、中、长三图各测双方侧位，每个政策六场，共36场。双方300金币、两个初始工人，敌方真实支付两名投矛兵并正常排队生产；无AI，显式提供完整科技，正常60Hz、正式迷雾与实际运输。除开局预购方案，其余在第一次合法发现敌兵后提交一次响应，观察90秒。

| 响应 | 金币支出 | 法力支出 | 两工人均存活的场数 | 其余结果 |
| --- | ---: | ---: | ---: | --- |
| 不干预 | 0 | 0 | 0/6 | 六场工人全部死亡 |
| 发现后补一名斧兵 | 45 | 0 | 0/6 | 推迟失守，但最终仍丢失全部工人 |
| 发现后单次雷击 | 0 | 40 | 0/6 | 减少敌兵，但剩余敌兵仍可摧毁经济 |
| 发现后购买两斧两矛 | 210 | 0 | 5/6 | 长图西侧损失一名工人，其余工人存活 |
| 开局预购两斧两矛 | 210 | 0 | 6/6 | 提前投入保住工人，不能据此认定该开局全阵营最优 |
| 发现后雷击并补一名斧兵 | 45 | 40 | 6/6 | 六场两工人均存活，显示法术与补兵组合的具体救场价值 |

短图西侧发现到首次工人受击约1.25秒，补兵实际出生约1.82秒后、首次攻击约6.18秒后。长图西侧发现到首次工人受击约1.53秒，补兵首次攻击约6.23秒后。因此加长地图主要延后敌军抵达，而不是让末端临时补兵变成即时救援。不能只看首个受击判断失败：单斧政策也曾在响应10秒后保留工人，但之后仍失守，故加入首次/最后工人死亡与最终存活记录。

完整科技和零人为操作延迟属于明确的受控条件，不证明正常开局的研究可负担性、真人操作成功率或其他阵营效果。两斧两矛比两名敌矛投入更多金币；雷击组合还使用法力，不能当作等价金币交换。地图侧位下矿工站位/运输不同，不根据这一个案例断言新的遍历顺序问题。

报告economic-counterplay-36-271.json；工具analyze_economic_counterplay.py验证36身份覆盖、源文件哈希、招募/施法成功、真实支出、金币收支及合法发现后的响应。输出economic-counterplay-36-summary271.json及CSV。攻击释放与命中分别记录；击杀统计还可能包括敌方工人，不把4击杀误读为击败4名作战兵。

## 已采用的AI规则

旧规则主要按敌兵价格选单体法术目标；只有一名便宜敌兵、且基地尚未进入通常威胁范围时，可能忽略其真实袭矿。现在仅凭当前合法可见敌兵识别：目标是己方存活工人，且已在前摇或进入实际攻击距离，才认定经济攻击。不读取隐藏敌军的目标关系，也不因地图上存在敌兵就提前施法。

- 便宜袭矿者可触发单体控制、雷击等应急动作，不再要求至少两名敌兵或95金币身价。
- 可直接击杀袭矿者的雷击优先级高于普通群体法术准备；正在袭矿的前摇也获得控制优先级。
- 重击/致命前摇仍优先于一般经济骚扰；绑定目标不会绕过原有控制重复检查。
- 已确认经济攻击可解除群体法术储蓄限制，实际费用、解锁、冷却、射程和视野仍由统一命令接口裁决。
- 不改变单位价格、攻击数值、地图几何或工人自然视野。
