# 实体查询缓存、绘制排序复用与 RC38 双平台交付

RC38 在不改变战斗规则的前提下收紧运行时热路径。`BattleSim.actor(uid)` 为单位、建筑和基地建立 UID 到实体的索引；每次取用仍检查实体当前生命值，死亡实体会从缓存移除并回退到原有线性扫描，因此不会把已死亡单位重新当作可命中目标。生成单位和建造建筑会即时写入索引，战斗开始、重置和集合变更会重新建立缓存边界。

`BattleView.ordered_units()` 在同一个模拟 tick 内复用单位排序结果。排序比较器、物理投影点、近距离 tie-break 和道路/上下路顺序保持原实现；模拟 tick 推进、单位移动、死亡清理或集合变化后才重新计算。1200 项重复/近阈值/采矿锚点/不变顺序的等价性检查通过，说明该复用没有改变遮挡层级或动作帧顺序。

构建工具还把资源扫描从递归 `rglob` 改为跳过 `.godot` 导入缓存和 `output` 生成物的受控遍历。运行资产输入扫描收敛为 455 个正式资源路径；Windows/Android 导出不再依赖 QA 缓存树的偶然内容。
