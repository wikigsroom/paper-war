# 单机地图剧情合同与路线分支验收

本项目的单机地图采用“地图即叙事场所”的约束：每一张地图都必须有自己的战前冲突、地图地点动机、可执行战斗目标、战后结果和证据旗。地图是否线性由剧情需要决定，线性、分岔、并行、汇流与回访都属于允许的路线形态；“非线性”不是每张图都必须有多条路，而是战役图不能被隐含成只有一条不可回访的固定顺序。

## 数据绑定

五份运行数据通过稳定 ID 连接：

- `game/data/maps.json`：战场节点、道路、矿点、建造位、目标锚点和地图设计卡。
- `game/data/campaign.json`：双方阵营、开局资源、AI 阶段、胜利条件与战前/战后对白。
- `game/data/story.json`：每张地图的故事事实、战前场景、战后场景、提示和证据旗。
- `game/data/campaign-narrative.json`：剧情目标为什么发生在这张地图，以及道路和目标锚点的地理绑定。
- `game/data/campaign-flow.json`：章节层、解锁条件、后继节点、分支和汇流。

运行时以 `campaign.json` 的关卡 ID 进入战斗，以同一 ID 读取故事与地理档案；不会因为地图名称、显示顺序或旧 `predecessor` 字段改变而丢失剧情绑定。

## 当前验收结果

可执行校验脚本为 `tools/paper-warfront/verify_story_map_contract.py`，最近一次结果保存在 `output/qa/paper-warfront/story-map-contract.json`：

- 200 张地图、200 个可玩关卡、200 个故事事实、200 个地理叙事档案和 200 个路线节点全部一一对应。
- 10 个章节完整覆盖全部关卡；每张图都有战前/战后文本、目标、目标锚点和证据旗。
- 战役图当前有 50 个分支节点和 50 个汇流节点；几何数据中有 60 张地图具有真实多路长度差异，140 张地图保持单主路用于节奏控制。
- 每个叙事档案的道路列表和目标锚点都能在对应地图的实际边上找到；章节层的页面集合覆盖全部 200 个关卡。
- 本次校验共通过 6531 项数据合同检查，失败项为 0；其中包含每张地图的实际几何分叉数与展示分叉数一致性检查，并硬性要求战前场景、战后场景、剧情线、证据名和关卡标题保持地图级唯一，防止新增地图复制通用剧情模板。
- 护送与截击目标的 HUD 距离沿单位当前道路和已选分支计算真实道路长度，不再用横向坐标差代替；目标位于另一条未选分支时显示“需改道”，胜负判定使用同一条几何路径规则。
- Godot 4.7.2 原生战役路线测试又通过 103595 项、失败项为 0，覆盖 64 条开局选择路径、552 条章节内最小路线顺序、实际解锁/汇流、存档往返和旧存档迁移；RC37 结果见 `output/qa/paper-warfront/campaign-routes-rc37.json`。RC36 的旧结果仍作为历史快照保留。

这项校验检查的是数据绑定和路线结构。它不把自动化检查冒充成 200 场人工通关、完整数值平衡或 Android 真机验收；这些仍按发布验收文档单独记录。

## 设计执行规则

新增或修改单机地图时，必须先补齐地图设计卡，再补齐同 ID 的故事事实和地理档案，最后把节点放入章节层。剧情目标必须落到地图的道路、矿点、建造位或目标锚点上；仅改标题、换颜色或复制上一关对白不能通过合同。需要线性地图时保留单主路，需要多路地图时必须让分路产生可感知的抵达时间、经济、视野或目标风险差异，并在战役图里写明分支的解锁与汇流条件。
