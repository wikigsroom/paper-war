本轮修复的是正常 AI 已识别危险攻击、却被单目标价格门槛再次否决的问题。预算 AI 的扩张与跨院试验见 [128](128-采矿扩张节奏与科技兑现复核.md)，仍保持默认关闭；本章的法术判断用于正常策略和候选策略。折纸 UI 沿用用户指定 `sub2-image-gen / gpt-image-2.5` 已生成并检查的 38 项资源，素材版本仍为 rc16，交互与程序版本单独记录。

Windows EXE 与 Android APK 已原生导出并核验为 **3.0.0-rc20-preview**：[Windows 下载](../../release/3.0.0-rc20-preview/PaperWarfront-Windows-3.0.0-rc20-preview.zip) · [Android APK](../../release/3.0.0-rc20-preview/android/PaperWarfront-3.0.0-rc20-preview.apk) · [随包验证范围](../../release/3.0.0-rc20-preview/preview-verification.json)。实际包中的逻辑、菜单、纸页、移动布局、字体、纹理和启动场景均已核验；Android 实体硬件与整体平衡仍未验收。

## 判断冲突与修复

`tactical_ai.gd` 已把危险前摇优先排到最高目标，但随后要求目标价格至少 95、附近有多个敌人或基地／矿工受威胁。单个 45 金币刀盾卫在战线中段即将击倒残血单位时，既被选为最高威胁，又被视为“不值得施法”。

现在，能实际阻止这次攻击的法术可通过单目标实用性判断，随后仍走原有的解锁、法力、冷却、目标和战争迷雾检查。

| 法术 | 新的单目标危险前摇判断 |
| --- | --- |
| 绑缚 | 能中止当前前摇，可响应已识别的危险攻击 |
| 夺印 | 改变敌方归属并清除当前目标与前摇，可响应已识别的危险攻击 |
| 破阵印／雷击 | 仅当按实际防御规则计算的伤害足以击杀攻击者时作为这次攻击的阻止手段 |
| 根缚 | 只限制移动，不把它当作已经开始攻击的打断手段 |

原有多目标、贵价目标及基地／矿工防守条件继续使用。没有改变任何法术效果、金币、法力费用、冷却、单位伤害、研究或生产时间。

## 同一观察器的前后结果

`test_ai_spell_budget.gd` 扩展至 258 项。新增用例在两侧核验三院绑缚、印甲雷击、根缚和夺印，隔离可用法术，覆盖可见危险单兵、普通非致命攻击、真实隐藏敌军、差一法力、未完成冷却和雷击后仍存活的敌兵。坐标、血量、可用法术与前摇是明确的受控夹具，不能作为普通开局、科技付款或整局胜率证明。

完整归档的修复前运行目录使用同一最终观察器，**258 项中失败 30 项**；最终源码 258 项全部通过。先前 170 项诊断观察器曾暴露“雷击造成伤害但未击杀，也未打断”的错误假设，最终判断按实际防御伤害和法术效果修正，不能把该中间结果当作最终检查。

完整当前源码机制检查 **64 组、14,128 项通过**。输入散列和测试观察器记录在 `output/qa/godot/core-alignment-rc20/solo-control-regression/report.json`，没有以新增检查数替代实际行为和边界断言。
