# 迷雾呈现、单位与地图比例 · rc21

本轮处理两个直接影响战场阅读的问题：未知区域原来只在道路附近画窄条，地形与小地图没有相应遮蔽；单位相对于场景偏大，地表紧贴底部军令，土层和高低道路的空间不足。现在使用整个舞台的纸色雾幕，并分别调整地图横向、纵向、纸偶大小和地表位置。

Windows与Android已交付 **3.0.0-rc21-preview**，Android版本码30020，范围见[最终包验证](../../release/3.0.0-rc21-preview/preview-verification.json)。65组15252项机制、两包各18组2322项、八配置26779项、六EXE场景、157项焦点、270项纸页、411项军令、98项UI风格及38项素材绑定通过；Windows ZIP随附一致验证记录。

本项目实际EXE对比：[地图与兵体](../../output/qa/godot/fog-render-rc21/figures/map-and-units-before-after.png) · [上下路雾幕](../../output/qa/godot/fog-render-rc21/figures/fog-before-after.png)。左侧是本作rc20，右侧是本作rc21，不是原作画面；原始截图、加工哈希与用途见[图表记录](../../output/qa/godot/fog-render-rc21/figures/comparisons.json)。

## 呈现差异及正式修复

| 问题 | rc20实际表现 | rc21实现 |
| --- | --- | --- |
| 未知区域 | 道路附近约86逻辑像素窄带；路外背景、桥和土层大部分清晰 | 原生网格覆盖完整战场高度，压低未知背景、地形、桥梁和纸层的对比 |
| 多条道路 | 窄带难以表达整层未知，也容易留下硬边 | 每条实际道路独立取当前/探索区间；上下路中线采用柔和过渡。下路侦察不能揭示桥上敌军 |
| 探索与实时敌情 | 对象过滤存在，但整体雾幕和小地图表现不足 | 当前区间内清晰，探索后失去观察采用较淡雾，从未探索采用较浓雾；移动敌军退出视野后消失 |
| 矿、空位和伏兵标记 | 地形标签可提前显示，矿点标记与现场状态的边界不一致 | 舞台仅在当前视野显示矿点、空建筑位和任务入口；未知敌方矿点不出现在小地图，旧矿点用记忆标记 |
| 路口点击 | 隐藏的路牌仍可返回非空热区 | 路牌显示和热区统一检查当前视野；军令中的预先选路仍可使用 |
| 小地图 | 道路图没有相应的未知/探索呈现 | 同一视野来源区分当前/探索/未知道路；敌军只显示合法实时情报，旧建筑只留空心标记 |
| 舞台两端 | 道路端点以外没有窄条覆盖 | 纸边继承最近道路端点的视野，避免两端出现明亮漏洞 |
| 镜头 | 导航已有视野门禁，旧默认中心固定10世界单位 | 按实际视窗宽度初始化/回城。网格只裁减待绘制部分，移动镜头不扩大视野 |

实现见[战场视图](../../game/scripts/battle_view.gd)、[纸色雾幕](../../game/scripts/theatre_fog.gd)、[视野服务](../../game/scripts/battle_visibility.gd)。世界坐标采样与颜色纹理固定，移动镜头不改变地形位置、路段情报或纸纤维位置；单个网格绘制，缓存几何并只构造当前视窗需要的列。

地形轮廓是公开的导航底图，未知区域保留低对比地貌剪影。动态敌军、实时矿状态、敌方建筑状态和目标点选独立走视野门禁；淡化地形不等于公开敌情。透明度只服务呈现，不能反写模拟、目标权限或网络投影。

## 单位、地图与画面空间

以下桌面值使用1600×900逻辑视口；1280×720运行窗口按0.8缩放。`unit.yin.axe`的定义身高为1.42世界单位，`unit.mo.giant`为2.0。地图长度仍来自实际道路定义。

| 项目 | rc20 | rc21 | 画面效果 |
| --- | ---: | ---: | --- |
| 横向世界比例 | 78 px/世界单位 | 112 px/世界单位 | 同一地图在屏幕上展开更长，节点不挤在一屏 |
| 纵向世界比例 | 48 px/世界单位 | 64 px/世界单位 | 高低道路、坡面和桥下空间更清楚 |
| 纸偶倍率 | 1.35 | 0.78 | 地图和单位的比例分开控制 |
| 普通兵绘制高度 | 149.53逻辑px | 124.05逻辑px | 1280窗口约119.62→99.24px，降低17.04% |
| 巨型兵绘制高度 | 210.60逻辑px | 174.72逻辑px | 体型比普通兵高约40.8% |
| 单屏世界宽度 | 20.51 | 14.29 | 42单位地图约2.05→2.94个标准视窗 |
| 地表下最低保留区 | 28逻辑px | 150.8逻辑px | 1280窗口约22.4→120.64px，可读土层不再紧贴军令 |
| 手机地图地表下保留区 | 28dp | 至少52dp、战场高度17% | 小屏也能看清道路和切土层 |
| 手机普通兵/纸工 | 随整个舞台缩小 | 作战兵至少60dp，纸工至少52dp | 缩放地形后仍能辨认和点选 |
| 手机巨型兵 | 原体型比例 | 以1.42身高为参考，最低约84.51dp | 保留2.0/1.42体型关系，不把巨型兵压成普通兵大小 |

比例规则与版本在[风格参数1.1](../../assets/paper-warfront/style-tokens.json)，运行副本`game/data/style-tokens.json`保持字节一致。绘制、目标框、动作释放点、攻击轨迹端点共用`unit_height`；地图坐标、路线长度、接触距离和移动速度仍由模拟处理。42单位地图的路长没有人为乘倍；此次增加的是地图占用屏数、土层空间和地图/兵体的视觉比例。

效果与风格修订记录见[rc21-fog-stage-r1](../../assets/paper-warfront/presentation-revisions/rc21-fog-stage-r1.json)。它绑定当前源码、规范、截图及实际包；与rc20实际APK比较的11项战斗/地图/AI编译脚本和规则/动作数据字节一致，为行军、付款和战斗节奏提供来源证据。

手机和同屏双人按整个道路高度适配舞台，分别预留土层；基地标题、建筑位和最大兵体都必须放入战场。常驻UI约束仍按完整视口扣除，至少70%的画面可见战场。

- [实际编译包迷雾](../../output/qa/godot/fog-render-rc21/release/fog-render/report.json)：桌面/手机各六张原生截图；同一观察器在rc20实际EXE上暴露场景高度和小地图问题，在新包上检查修复。原图、哈希、编译脚本输入均保留。
- [地图比例与实战](../../output/qa/godot/fog-render-rc21/release/stage-proportions/report.json)：200地图检查最大兵体、基地、建筑位、土层和手机可读性，另外以正式初始资源、真实AI招募和行军记录交锋。两种显示配置共22902项、十二张截图；不是人类试玩或设备FPS测试。
- [同屏与联机视窗](../../output/qa/godot/fog-render-rc21/release/duel-stage/report.json)：最高地图的大屏分屏、最低800×600分屏和手机两侧联机视窗共10项几何检查。小手机分屏由真实菜单入口阻止；不将绕过入口构造的未支持尺寸当作可玩场景。
- [额外矮屏边界](../../output/qa/godot/fog-render-rc21/stage-short-boundary/report.json)：实际编译EXE在1136×568、密度2下复核全部200地图，18651项通过；保留六张原生截图及巨型兵、基地标题和建筑位的边界记录。
- [机制回归](../../output/qa/godot/fog-render-rc21/formal-reach/regression/report.json)、[八种移动配置](../../output/qa/godot/fog-render-rc21/release/mobile/mobile-matrix.json)、[实际EXE启动](../../output/qa/godot/fog-render-rc21/release/mobile/export/report.json)及菜单/纸页/军令检查纳入最终包核验。
- 38项折纸UI、角色整身动作和环境位图沿用已检查版本。本轮没有新增图像生成；`effect.common.theatre_fog`是独立的代码效果，规则见风格参数，不冒充Sub2生成图或外部3D素材。

**已保留的失败记录：** 旧EXE的全高度雾幕与小地图检查、旧EXE的土层/手机可读性检查，以及最初移动观察器直接点未侦察路口的记录。该观察器后来补充真实视野来源，并继续验证侦察前无热区、侦察后可切换；没有为了通过检查取消正式迷雾规则。

当前仍需实体Android设备验证触控、GPU表现、后台恢复和实际帧率；用户本轮确认暂无设备。原作同条件视野/时序实测、200关逐关人工通关、整体阵营平衡和真人互战未验收。预算AI候选保持关闭，之前的阶段矩阵不被本轮图片比例或迷雾测试替代。
