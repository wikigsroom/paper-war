# rc6 战斗衔接与反馈调优

本轮针对实际攻击衔接与密集反馈清理做局部调优。继承 rc5 的十阵营、60 个独特兵种、10 名工人及两种召唤物和整身动作帧资源。

## 攻击收势

原逻辑在攻击释放后的下一模拟步重新选择目标；原目标死亡或出射程时会立即进入行走，截断整身收势帧。现在攻击释放后按每个单位的既定 recovery 时长完成收势，然后重新寻敌、行军或装填。不会锁住伤害，眩晕和束缚仍优先中断动作。未修改单位成本、伤害、攻击间隔和 AI 参数；行军及追击节奏可能因完整收势稍微变慢。

## 反馈清理

粒子、特效、飘字改用原数组稳定压缩，依次更新存活元素后一次缩短数组。替代每帧复制三个数组、对每个到期元素做查找删除。保留绘制顺序、运动积分、预算和暂停行为。这是分配和算法改进，未据此宣称手机帧率提升。

原生 Windows 无窗口微基准：650 个元素、一半到期，每组运行 1,000 次，预热后取五组中位数。旧清理合计 1,422,420 微秒，新清理 194,267 微秒，约为旧耗时的 1/7.32；输入构造时间排除。此结果只衡量清理代码，既不是战斗渲染基准，也不是 Android 帧率证据。原始结果见 output/qa/godot/tuning-rc6/cleanup-benchmark.json。

## 验证与交付

新增原生 Godot 检查覆盖全部 62 个作战及召唤定义：无剩余目标时仍完成收势、收势结束恢复行为、眩晕可中断；650 个混合寿命元素分别验证三种反馈列表的顺序与彻底清理。2,127 项通过。阵营、帧契约、友军伤害保护、工人动作及地图基础继续执行回归，报告位于 output/qa/godot/tuning-rc6。

新版 Windows EXE 与 Android APK 位于 release/3.0.0-rc6。APK 延续应用 ID 与签名，versionCode 为 30005。导出脚本验证签名、ZIP 及 ARM64 ELF 的 16KB 对齐，记录源码和二进制 SHA256。实际 EXE 另执行桌面及四种移动显示指标的六组启动截图检查。

Android 真机性能、发热与输入仍未验证；本轮没有完成 200 关人工难度验收，也没有重新生成已经审查通过的美术。rc5 交付与旧验收报告保留。
