# 同帧攻击与死亡结算更新

本轮修复58定位的第二项侧序缺陷，并保留59的移动接敌修复。正式兵种费用、伤害数值、地图、科技与AI策略没有因镜像结果而补偿调整。本作的结算约定见下表，不宣称这是未经实机测量的原作内部实现。

## 正式结算约定

| 阶段 | 行为与边界 |
| --- | --- |
| 单位推进 | 状态、寿命与被动能力先处理；合法完成前摇的攻击登记意图。位置暂存后恢复，让其他单位读取移动前的位置 |
| 攻击释放 | 复查存活、归属、控制及射程；攻击驱散先应用，再记录各次攻击的伤害、攻击序号与沉默状态。此时不扣血 |
| 移动提交 | 提交已记录的位置。没有移动的对象跳过额外锚点分配与写回；不改变道路、身体锚点或间距规则 |
| 投射物推进 | 本帧到期的投射物处理归属与反射，并登记命中；主目标已死亡的范围弹仍在最后目标点产生合法敌方溅射 |
| 防御与扣血 | 各次命中先计算保护、抗性与护卫效果，再按目标汇总；所有目标的生命统一提交后，才运行命中回调 |
| 命中与奖励 | 过量伤害按减免后贡献比例分摊实际伤害，实际伤害总量不超过剩余生命。每个死亡目标只计一次击杀，赏金/击杀法力只给单份减免后伤害最大命中的来源；同贡献时按稳定来源ID处理。同一来源的并发多段命中也只发一份奖励 |
| 死亡处理 | 命中回调后统一生成尸体与死亡反馈，处理死亡治疗/爆发的追加死亡。已经致死者不能由吸血或死亡治疗复活；死亡和尸体各生成一次 |

同帧已释放的攻击不被同帧致死或命中控制撤回。未完成的前摇仍会被控制打断；在释放阶段之前因状态伤害或寿命结束而死亡的单位不能攻击。范围、友敌归属和目标转换校验继续执行。预先命中的法术控制、持续区域与定时法术仍有各自阶段，本轮没有把全部游戏事件改成同一种同时结算。

投射物保存简短的释放上下文与源位置，而非持有完整死亡单位。发射者死亡后，已发射弹仍保有阵营能力、合法命中和击杀奖励；自身不获得复活性吸血。反射继续沿用实际所有权和不触发原攻击者命中能力的边界。

受伤产法的奖励按实际扣血计算，不按超过目标剩余生命的原始伤害计入，原比例与每秒上限保留。

## 当前源码验证

新增test_simultaneous_combat.gd的90项检查覆盖：

- 两种遍历顺序下的双方致死、两份合法攻击事件、单次死亡/尸体/统计。
- 同帧投射物命中、射手死亡后的双投、毒针和击杀法力。
- 同帧控制不撤销释放、已有控制和未完成前摇仍被打断。
- 实际伤害吸血、双方非致死吸血、物理反击致死不复活。
- 多攻击同目标的实际扣血分摊和唯一赏金。
- 死亡爆发、死亡治疗、建筑毁坏、友军转换、射程、状态致死、寿命和第三击控制。
- 一次性法术吸收只挡住一份同时到达的伤害。

移动接敌18项及以上90项已加入正式原生回归工具。回归范围扩展到所有权、采矿、动作帧、迷雾道路、法术、经济、研究、AI和关卡导演，24组共10750项全部通过。所有进程退出0、日志无脚本错误；检查前后源码指纹一致，七场付费观察的全部输入指纹与当前源码相符。该数量不是全游戏验收或平衡结论。

## 性能与剩余工作

120个存活混合单位、分岔与正式迷雾、120个60Hz模拟步骤的Windows原生无渲染观察：跳过未改变位置的锚点记录后，行军平均16.05ms、95分位23.34ms、最大31.30ms。优化前另一次观察平均17.67ms；不同调用存在机器状态波动，不把全部差值解释为代码收益。七场付费对局和三次侧序观察在优化前后的完整记录数值一致。

行军95分位仍超出16.67ms，尚未完成性能验收；该结果不是绘制帧率或Android硬件表现。木拓/白签的经济失守仍存在，需要继续调单位组合回报、兵团保护、科技和法术转型；不能把结算公平修复当成强弱已经平衡。原100场矩阵对应修改前源码，仅作为历史比较。

Windows EXE与Android APK仍是此前rc7-preview，尚未包含本轮源码，也不作为本次修复的运行证据。
