# 验收与制作计划

素材、技术与玩法分别验收。素材覆盖完整范围后仍需可玩切片；纸偶好看后仍需密集战斗中的读图和点选。

## 阶段与依赖

| 阶段 | 本阶段必须交付 | 通过条件 |
| --- | --- | --- |
| A 方向与素材基线 | 本文档体系、116 项登记、生成源图、候选资源、关节蓝图、原型规则与科技图 | 文件能读、引用不缺、造型能区分、状态真实 |
| B 印甲对墨骸闭环 | 资源、工人、三种作战单位/方、科技、出兵、施法、尸体、AI、胜负与重开 | 同预算选择和关键施法改变战线结果 |
| C 纸偶与操作切片 | 程序化部件、行走/攻击/受击/阵亡、选取、范围预览、HUD/导航、混音 | 实际操作尺度下好辨认、好点选、结果明确 |
| D 补齐三阵营 | 灯台、反弹、复制、保护、越线、巨型、攻城与高级法术 | 六组核心组合/反制成立，特殊状态无漏洞 |
| E 内容与规模 | 三地图、教学战役、挑战、AI 风格、压力预算 | 关卡教授战术，性能与保存稳定 |
| F 在线 1v1 | 同步、输入时序、摘要、匹配、恢复 | 实际双端对局和断线情境通过 |

当前任务完成 A 的资料与素材候选；B–F 为后续制作目标，不能写成已有运行成果。

## 素材检查

| 检查 | 要求 |
| --- | --- |
| 全量引用 | ID 唯一、来源存在、加工文件可读、头像与 rig 关联有效 |
| 透明与裁切 | 完整人物，不串邻格；基线/中心锚点正确；透明边无明显背景 |
| 图标功能 | 15 法术和16公共符号有不同母题，48px仍能辨认 |
| 材料与场景 | 纸材哑光，背景不抢轮廓，装饰灯不冒充产法设施 |
| 声音格式 | WAV 参数、时长和峰值有效；听感与混音另行检查 |
| 数据一致 | 单位/法术/建筑 ID 与科技授予一致，前置无环，三工人经济相同 |
| 可重做 | 每个导出能追溯源图、裁切或轮廓提取与工具版本 |

自动检查输出 [素材库检查报告](素材库检查报告.md)。技术检查不能自动批准图像母题；视觉审阅与运行审阅各有记录。

## 首个可玩切片的对局验收

建立可重放的基线命令与初始状态，对每个情境比较两种选择：

1. 开局补工人与开局补兵，观察早期压力和后续收入。
2. 同样金币买科技与买现成单位，观察等待和前线机会成本。
3. 同一交锋，补纸准确与误用，观察前排生存和后排输出。
4. 献祭健康兵与低血兵，观察剩余兵力、法力收益和后续反制。
5. 同一阵亡标记被多个祭司争用，确认只产生一个召唤结果。
6. 攻到敌方家门口与在中段打，确认补充距离和经济安全改变。
7. 连续招募、科技、导航和施法，确认菜单与提示不阻断操作。
8. 基地同时归零、暂停/失焦、重开，确认胜负与资源不残留。

补齐阶段增加：巨人前摇打断；反弹一次与直接伤害区别；复制禁止链；控制更新归属；设施被毁停止回法；突击落点合法。每次记录结果、命令日志和问题，不能只用屏幕中的火花判断伤害对了。

## 纸偶手感验收

同屏放入两阵营近战、远程、重型和支援，至少发生三次连续施法。检查选中目标是否稳定、范围是否与命中一致、军旗和背景是否遮挡身体、受击是否有重量、祭司/巨人的前摇是否看得懂。

进行 100%、75%、50% 显示尺度及常用 16:9/16:10 视窗检查；降低动态、关闭声音、灰度情况下仍能知道招募/施法成功。声音实际试听、重复播放、同类限流和警告可辨识性需要在运行环境中完成。

## 性能与完成证据

性能记录必须写设备、分辨率、单位/投射物/粒子数和录制条件；同时记录帧时间与纹理/提交预算。预算未达标时有具体缩减方案，不能以高端机器的一张截图声称全部设备稳定。

每阶段交付包含可打开结果、验证方式、已知限制与下一依赖。未经对局验证的数值保留 `unbalanced-prototype`；未经接入的图像保留候选/视觉通过状态；网络阶段在有双端证据前保持未完成。
