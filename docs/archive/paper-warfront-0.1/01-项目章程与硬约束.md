# 项目章程与硬约束

工作名：《纸上兵戈》 / Paper Warfront。版本 0.1.0。

## 玩家承诺

玩家用少量持续可达的操作，改变一条横向战线上的军团交锋。胜利来自经济投资、科技时机、兵种组合和准确施法。纸甲折损、补纸、拾纸成兵与盖印重击把战术结果表现得清楚、有力、带喜剧性。

三位纸偶统帅争夺能够把愿望盖成现实的印章。印甲军想要永不破的甲，墨骸社想把退役军队折回来，灯符朝想复印整个朝廷。统帅一本正经，愿望荒诞；战役对白简短，战斗效果必须兑现世界设定。

## 必须成立的游戏边界

| 编号 | 约束 | 可观察的结果 |
| --- | --- | --- |
| G01 | 单位自主行军、接敌、攻击和继续推进 | 招募后无需逐个控制，也会攻向敌方 |
| G02 | 主资源只有金币和法力 | 经济、科技、招募共享金币；法术共享法力 |
| G03 | 三阵营采金基础相同，法力经济不同 | 印甲买升级、墨骸献祭、灯符保护设施 |
| G04 | 科技在当前对局内解锁并有前置与费用 | 解锁与出兵分别支付，具有机会成本 |
| G05 | 目标施法是玩家干预交锋的主要动作 | 合法目标、确认、取消与实际结果明确 |
| G06 | 地图长于一屏，镜头保持侧向阅读 | 可以看家门口、经济区和局部战斗 |
| G07 | 巨型、召唤、反制、保护、复制与控制都有规则边界 | 能反制，能追溯费用与归属，无无限循环 |
| G08 | 普通对局摧毁敌方基地获胜 | 双方生产、经济与完整胜负都成立 |
| G09 | 素材服务单位角色、状态和操作 | 看轮廓能辨近远程，施法后仍能选下一目标 |

纸张折叠、墨迹、印章和灯火属于表现与技能叙事。纸材数量、墨水浓度、纸面湿度、印章连击、领地染色不进入主循环；灯台负责产法力，不提供隐藏区域增益。技能新增须解释具体战术问题及反制。

## 美术与资产硬约束

- 固定正交侧视；纸偶由有限厚度片状几何和少量关节组成。
- 朱红、墨黑、青金分别代表阵营；蓝色代表法力，功能颜色不被装饰挤占。
- 字体、价格、冷却、生命和科技连线由代码画。图片中的生成文字不能作为正式 UI 文字。
- 角色、武器、纸城可由代码构造；不依赖人工雕刻模型、复杂蒙皮、动作捕捉或外部建模外包。
- 角色纸纹轻，场景对比低，战斗边缘清楚；相机自由旋转、写实布料、镜面金属和大型体积特效不在当前路线内。
- 稳定 ID 引用素材。源图、加工候选、运行资源分开，不能直接把整张素材板加载为单位。

## 技术与范围

主路线：TypeScript、Vite、Three.js、DOM HUD。模拟使用固定时间步、战线坐标与明确命令，渲染跟随状态。纸片受击和碎屑是视觉效果；普通战斗不需要三维刚体求解。外部模型如果以后确有用途，再作为独立决策引入。

完整产品内容目标为三阵营、教学战役、AI 遭遇战、挑战和 1v1。首个可玩阶段只做印甲对墨骸的完整攻防；灯符随后补全。网络同步、匹配和断线恢复作为独立工程阶段，素材基线不代表这些系统已经完成。

## 环境与完成判断

所有工作使用 Windows 原生进程和直接请求，严格禁止 Docker、WSL 与虚拟化环境。图片用指定 `sub2-image-gen` / `gpt-image-2.5`。浏览器使用后关闭本次不再需要的标签。

基准数值与性能预算都是设计起点，需记录设备和实测结果。素材导出成功、图片好看、代码可编译都不能单独证明游戏体验达标。资产正式接入必须通过操作尺度、动画、密集交战和对应战术情境的检查。
