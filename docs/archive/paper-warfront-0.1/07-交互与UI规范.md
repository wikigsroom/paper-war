# 交互与 UI 规范

玩家连续处理招募、施法、科技和导航。桌面鼠标与键盘为首要体验；触控横屏作为后续适配，不以现有概念图声称已支持移动对战。

## 画面布局

顶部是金币/法力、招募、法术、建造入口和科技；各组用途清楚。工人加四个常规作战入口共五个，召唤兵不出现付金招募按钮。法术五个，随解锁展示；不能照概念图的四图标示例限制实际规则。

底部只保留细战线导航，包含双方基地、矿区、设施、单位点与当前视窗。主画面显示局部交锋，允许两个基地都在镜头外。科技树、设置和长说明按需打开。持久界面在常用桌面视高里尽量不超过 20%，中心与下中部供交锋和瞄准使用。

参考 900px 高画面：顶区约 104px，底区约 40px，操作图标主体至少 44px，费用数字约 14px。高度不足时优先收起标题和常驻说明；更小横屏使用紧凑模式与单位/法术页签，不通过把字缩到不可读来适配。

## 主操作

| 动作 | 输入 | 状态反馈 |
| --- | --- | --- |
| 招募 | 左键点击已解锁入口；原型快捷键 1–5 | 扣金、入队、待产数量；不足时给原因 |
| 施法 | 点法术或 Q/W/E/R/T，再点目标/地面 | 可用范围、目标边框、确认反馈、扣法与冷却 |
| 建造 | 点建造入口，再点合法固定位 | 空位框、费用、确认后建筑出现 |
| 科技 | 点科技入口或 F | 前置连线、状态、费用与研究进度 |
| 导航 | 边缘平移、A/D 或导航点击/拖动 | 镜头到目标战线位置；入口不随镜头移动 |
| 定位 | Home 定位己方；Space 定位最近有效交锋 | 视窗 bracket 与镜头对应 |
| 取消 | 右键或 Esc | 退出目标模式，不扣费用 |
| 暂停 | 独立暂停入口或 P | 本地对局暂停；网络模式另行设计 |

上述键位是项目方案，不声称为 HD 原键位。快捷键需显示在帮助中，接受重绑规划；输入框聚焦时不触发对局快捷键。释放窗口焦点时清掉持续导航按键，避免回来后镜头漂移。

## 状态模型

按钮至少表达：未解锁、可研究、研究中、已解锁可用、资源不足、冷却/生产中、当前选中。形状、锁、进度罩与颜色共同表达。禁用按钮仍可查看原因；不要仅把 opacity 降低就丢失解释。

选法术后进入 `targeting`，合法单位呈浅纸边，非法目标呈限制标记。单体恢复不能把敌人或基地高亮成合法目标。区域法术只显示范围和实际可受影响对象，不高亮装饰纸灯。

多兵重叠时候选先按合法性过滤，再按指针距离与可见身体层确定；用 Tab 轮换当前候选并显示稳定轮廓。首次点击确认正在预览的 ID，不在点击瞬间换到另一单位。目标在确认前失效时失败且不扣费。

UI 的点击不穿透战场；拖动导航不能同时施法。科技树打开时对局继续，但点击和快捷键由菜单接管。Esc 先关闭最上层状态；右键只取消瞄准，不同时弹系统菜单。所有费用以命令确认结果为准，视觉预览不提前扣费。

## 科技图与说明

科技节点为方印，前置边可见。选中的说明放在独立侧栏或不覆盖节点的区域。说明包含：名称、费用、研究时间、前置、目标类型、一句战术用途；故事留到图鉴和战役。

研究支付后明确显示进度，完成后出现新入口反馈。资源不足或前置不满足的原因必须可见。法力升级是科技结果；工人、单位招募和建筑建造仍单独支付。

## 字体与图标

中文正文用系统黑体栈，标题可用楷体；数字用等宽栈和稳定宽度，避免资源变化时按钮跳动。字体均使用本机系统/用户已授权资源，不把特定字库随包分发。主题 CSS 见 [theme.css](../../../assets/paper-warfront/ui/theme.css)。

生成图标只承载母题。名称、费用、蓝色/金色资源标、快捷键、锁、进度与边框由 DOM/CSS 管理。复制、保护与恢复要用不同形状；召唤和招募不要共用一个图标造成语义误导。

## 反馈与声音

有效操作轻纸签声；无效操作短反馈和文字原因；解锁用盖印声；重击用低纸木撞击；补纸用柔和回声；墨法用低墨卷；灯符用清楚短亮音。声音事件来自模拟或已确认的 UI 行为，鼠标 hover 不持续播放声音。

场内限制同类音的密集播放：脚步按距离/频率抽样，普通命中不每兵叠满；重击和关键施法有优先级。按镜头距离衰减，警告有最小重复间隔。音乐为低音量背景，不能淹没资源和法术确认。20 个 SFX 和三段阵营节奏草稿需后续听感与混音验证。

色弱检查用阵营形状、敌我标、虚实线和锁来补颜色；降低动态时关闭相机抖动和装饰脉动，仍保留命中与状态必要反馈。键盘 focus 可见，按钮有语义名称和状态，声音可静音且保留视觉反馈。
