# 当前版本差距审计

对象：Godot 1.0 工作区源码。原版研究证据见 [事实台账](01-来源与事实台账.md)。本文件的结论只评价地图与关卡空间，不推翻已有包体、菜单或单位规则验证记录。

## 1. 实际结果

**三个场景主题，一套机械地图；十五个战役关卡，全部拆基地。** 场景切换没有改变路径、基地/矿点/塔位、采矿时间或地图目标。不存在岔路、路标、高度曲线、逐图设施位置或空间任务区域。

| 当前内容 | 审查到的实现 | 实际后果 |
| --- | --- | --- |
| 印原 / 墨沼 / 灯岭 | map ID 切换背景和纸松/芦苇/装饰灯 | 只能改变视觉，不能形成地图选型 |
| 基地和矿点 | 基地 X=2/54，矿 X=6/50；所有局固定 | 攻击矿区的距离、经济暴露关系不变 |
| 建造位 | 每方固定两个槽位：3.5/8.5 与 52.5/47.5 | 无逐地图可防守设施空间差异 |
| 采矿 | 独立工人计时，固定单矿，无服务容量/排队/分配 | 加工人只增加相同线路吞吐量 |
| 地表 | floor_y 固定，只有画面上的装饰错位 | 纸岭是背景，不是路径起伏 |
| 单位位置 | 只有 x；最近敌人和范围伤害用 abs(x差) | 一旦添加视觉分岔，会发生跨路近战/错选/错误范围伤害 |
| 建造过程 | 扣费后立即成为可用建筑 | 没有施工受压和抢拆窗口 |
| 战线与导航 | front 只返回一个数；小地图所有单位按 x/56 投影 | 无法阅读或快速定位不同路线威胁 |
| 对手 AI | 按单线基地距离判断威胁，无路线或分路状态 | 无法处理绕行、护矿、汇流与多点防守 |
| 十五战役关 | win 均为 destroy_base，变化来自资源/预解锁/AI | 缺少矿线截击、护送、节点保护等地图驱动任务 |

`balance-prototype.json` 虽含 map 块，模拟没有读取该块作为地图定义；坐标在脚本里固定。数据里出现“map”不意味着具备地图系统。

## 3. 原生 Godot 比对实验

保持印甲对墨骸、双方 AI、完整科技、双方 420 起始金币、标准反制 AI、种子 137 与固定 60Hz 相同，只分别传入 `stamp-plain`、`ink-marsh`、`lantern-ridge`。每局执行 7200 步（120 秒），逐步记录玩家、单位、建筑、基地、弹体、状态、事件、AI 时钟与 RNG 状态；排除地图名字和画面数据。

**结果：三份完整模拟轨迹的 SHA-256 完全一致。** 完整散列、初始位置、首次伤害时刻、双方统计和基地血量在 [current-map-probe.json](current-map-probe.json)。这证明本次对照场景里 map 选择没有机械影响；源码审计进一步解释了原因。它不证明所有可能对局，也不评估玩家主观乐趣。

复现方式：Windows 原生 PowerShell，从仓库根目录执行：

```powershell
& '.tools/godot/Godot_v4.7.2-stable_win64_console.exe' --headless --path game --script 'E:/dev/vibe-game/剑与勇士类/tools/paper-warfront/research/probe_map_equivalence.gd' -- 'E:/dev/vibe-game/剑与勇士类/docs/research/swords-and-soldiers-map/current-map-probe.json'
& 'C:/Python313/python.exe' 'tools/paper-warfront/research/build_map_audit.py'
```

脚本不修改游戏规则，不使用 Docker/WSL/虚拟化环境。该实验是研究审计，不是新的地图功能通过测试。

## 4. 现有数值怎样固化了空间

安全稳定状态下，每位工人走固定单程 4 距离，速度 1.25，采 1.2 秒、交 1 秒、载 8 金。理想往返周期为 `2×4/1.25 + 1.2 + 1 = 8.6 秒`，约 `0.93 金/秒/工人`。这是本作公式，忽略离散步长与接敌，不是原作测量。三种场景共享这条线路。

从作战出生点 X=2.65 到中点 X=28，不计生产、射程、战斗和控制，折斧兵速度 1.1，理想行军约 23.05 秒；炮车速度 0.54，约 46.94 秒。地图本应让这类增援窗口随路线和设施位置发生变化，现在所有场景完全相同。

当前最多 6 工人属于本作规则，开发者 AI 示例提到的 10 工人属于原作示例。后续先测服务能力和战术节奏，不直接把本作上限改成 10 便宣称经济对标完成。

## 5. 必须纠正的验收结论

已导出的 Windows/Android 包、规则检查、AI 可通关轨迹和 UI 截图仍是有效的程序验证。它们未覆盖地图结构差异、路径选择、逐图经济分布与空间任务，所以“完整对标地图”不能据此成立。三地图的说法应改为“三场景主题，共用一套机械地图”，原有 1.0 交付记录保留。

优先级：P0 是地图数据、路径/坐标、目标选择、经济和建筑位置；P1 是路标、小地图、地图 AI 与目标导演；P2 才是场景素材扩展、更多关卡和重新导出。先补视觉会把同一套地图错误继续复制到新内容中。
