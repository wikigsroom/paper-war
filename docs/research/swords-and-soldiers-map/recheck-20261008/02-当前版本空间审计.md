# 当前版本空间审计

本文件评价 2026-10-08 的 3.0.0-dev 工作区。旧版 1.0 的“一套平地、纯 X 判定”已不是当前完整事实；当前已有路径图、矿点运输、施工状态、二维命中和多任务。问题转为这些机制能否稳定运行、地图是否经过设计、表现能否让玩家读懂。

## 1. 配置数量与地图设计证据

[完整审计 JSON](current-map-audit.json)记录输入散列，避免之后的数据变更混入本轮结论。

| 实际检查 | 结果 | 需要纠正的结论 |
| --- | --- | --- |
| 200 地图几何散列 | 全部不同 | 只能证明数据不同，不能证明逐关战术成立 |
| 拓扑签名 | 150 单线 / 50 单处分岔 | 拓扑简单符合方向；数量比例本身没有原作依据 |
| 矿、设施在边上的相对锚定 | 180 图共用基础布置，20 图增加桥上设施 | 目前仍由模板替代大量逐图地点设计 |
| 所有地图矿点 | 都是双方各两矿、无限资源；没有岔路矿 | 不要求必须新增中立矿；应按关卡问题选择实际布置 |
| 50 张岔路图 | 20 图有桥上设施，30 图没有桥上经济/设施对象 | 需要逐图给出敌情、目标或汇流节奏的依据 |

| 长度 | 34–52.82 世界单位 | 路长已带来实际时序差异，不应再说全部机械相同 |
| 主目标 | 70 拆基地、30 运金、30 保护、30 护送、20 生存、20 截击 | 任务类型已存在；还需验证每类目标与地点之间的关系 |

拓扑和锚定模板相同的地图仍可因距离、初始阵容、事件而玩得不同。本次不把它们武断归并成“两张地图”，而是将 **200 张地图的设计验收整体标为未完成**。

## 2. 原生经济测量：外矿停运是 P0

条件：Godot 4.7.2 原生 headless、60Hz、种子 137、关闭双方 AI、双方同印阵营。清除开局单位后在基地附近放指定工人数，使用公开 `mine_priority` 命令；测 120 秒。无生产耗时、购买费用、敌人干扰，所以结果只测运输，不代表人类开局效率。

| 地图 map.01.01 | 工人数 / 策略 | 首次回款 | 120 秒回款 | 每 30 秒回款 |
| --- | --- | --- | --- | --- |
| 左方近矿 | 1 / 近矿优先 | 5.77 秒 | 160 金 | 40 / 40 / 40 / 40 |
| 左方外矿 | 1 / 外矿优先 | 14.08 秒 | 11 金 | 11 / 0 / 0 / 0 |
| 右方近矿 | 1 / 近矿优先 | 5.48 秒 | 168 金 | 40 / 40 / 48 / 40 |
| 右方外矿 | 1 / 外矿优先 | 13.57 秒 | 88 金 | 22 / 22 / 22 / 22 |
| 左方自动分配 | 3 | 5.77 秒 | 480 金 | 120 / 120 / 120 / 120 |
| 左方自动分配 | 4 | 5.77 秒 | 491 金 | 131 / 120 / 120 / 120 |

上述左方外矿工人结束状态：`job=mine, mine=mine.0.1, edge=ground.0, s=0, cargo=0`，路由结果为 `exit=west, next_edge=ground.0`。它已回到基地，准备下一趟，但下一条边仍是所在边。

源码原因：`route_to` 枚举当前边两端，再求节点最短路径。在边端点附近，一条等长方案可能把当前边再次作为第一条边；`move_to` 随后反复将 actor 放回同一个端点，32 次保护循环耗尽也没有移动。这是路径执行缺陷，不是合理的经济代价。[map_runtime.gd](../../../../game/scripts/map_runtime.gd)

优先修复并补测两方向、端点、跨两边/多边、分岔以及持续往返。之后才能调矿工价格、产量或关卡预算，避免用数值补偿寻路错误。

### 理论收益也没有支持当前外矿说明

按当前印工人速度、货量、采集与交货耗时，单工人无排队的理论外矿收益仅为近矿 **54.49%–57.16%**。这是分析估计，不是发生停运后的实测收益，也不是原作数值。

外矿仍可能因增加总采集能力而有用，但必须证明近矿已经成为服务瓶颈或分配限制。当前 `capacity` 同时被用于“到矿工人的并行采集”和自动分配惩罚，两种含义未清楚统一。不能把增加到第四名工人后只多 11 金的实测结果当作扩张已经成立。

左右近矿的距离也不同；对称对战基准缺少这项不对称的明确设计理由。同阵营样本已经出现 160/168 金差异。任务关可以不对称，但必须说明意图和补偿。

## 3. 路线与接战测量

在五张印域岔路样本上，同一折斧兵单独行军，主路与纸桥的汇流时间差约 1.43–1.60 秒。全 50 图的几何分析估计为 1.43–1.77 秒。改路已经改变时序；是否值得付这个时间，仍要结合当前敌人位置、跨路射程和任务边界验证。

同一批实验中，三张地图各放一名双方折斧兵同时出发，首次命中为 11.07、14.67、16.13 秒。没有计算招募/科技耗时，不能当成玩家开局首次交战统计。[原生测量 JSON](native-probes.json)

当前纸桥默认抬高约 2.15–2.29 世界单位，而印塔射程为 4.3。二维射程并不会因为单位去了另一条路就自动失效。因此“纸桥避开主路阵地”要逐位置检查，不能仅凭上下分离写入通用地图说明。

## 4. 已交付画面与工作区表现

已交付 2.0 的真实截图显示：背景山岭精细，但单位脚下是悬在背景上的宽线段；道路交叉、矿洞和路标挤在同一高度；单位互相遮挡；大面积文字与按钮抢占战场阅读。它可用作历史版本的表现证据，不能充当修改后的 3.0 截图。

当前 `battle_view.gd` 仍逐边绘制三层粗折线，再放矿、基地与路标；新增 `theatre_ground.gd` 尚未接入该绘制入口。因而“连续主路”已进入数据，但实体地表表现仍未完成。`ground_y_at(x)` 还是把 `(x,0)` 投影到最近路径，不能保证取得该 X 上指定主地表的高度；后续地表装饰应使用明确的 surface 采样。

## 5. 镜头尺度与空间 AI

当前渲染的横向比例为 `PX=78`，逻辑视口基准 1600 × 900，所以一次横向视窗约覆盖 20.51 世界单位；34–52.82 的全图约为 1.66–2.58 个视窗。默认窗口截图虽为 1280 × 720，`canvas_items` 会缩放逻辑视口，不能直接用截图像素除以 78 得出视野。[视口配置](../../../../game/project.godot)

因此设计卡要检查玩家的正常局部视窗：矿区、施工和前线可能不同时可见。导航、地点跳转、受扰提示和路标反馈是地图体验的一部分。长图增加信息切换成本，不只有单位行军时间。最终渲染使用 `PX/PY=78/48` 的表现比例，研究白盒图则保留 X/Y 同尺度，二者用途不同。

当前 AI 并非没有空间判断：`choose_routes` 会比较出口长度、沿路敌我强度、敌方建筑和己方矿；`choose_mine` 会比较基地欧氏距离、载金奖励与附近敌人；施工也会检查敌人距离。但它尚未按实测完整运输周期、增援到达或设施回本窗口选择投资，分配计算还受当前矿工停运影响。[tactical_ai.gd](../../../../game/scripts/tactical_ai.gd)

这轮 49 组夹具禁用了 AI，不能据此宣布 AI 对局通过。后续对 W01–W03 要另测它面对发展、外矿和快压时能否产生可看懂的反应。任务脚本、普通对手决策和玩家规则应分别记录，不用固定出兵表掩盖位置投资失效。

工作区规则数据版本为 3.0.0-dev，而 `project.godot` 的应用版本仍是 2.0.0。这再次说明当前是未完成的重做工作区，不能把研究记录或新数据当作已发布 3.0。

## 6. 本轮排序

| 优先级 | 工作 | 验收重点 |
| --- | --- | --- |
| P0 | 连续运输及方向对称性 | 每个合法矿能多次往返；无原地换边；错误有日志 |
| P0 | 地图经济容量与分配含义统一 | 新工人的边际收益、矿服务瓶颈可解释 |
| P1 | 三张手工地图的矿、塔、路长与目标 | 两种打法各有成立条件；AI 按相同规则反应 |
| P1 | 连续地表、足点、点击、预览、导航 | 画面能够说明真实运行状态 |
| P2 | 有必要的分岔与任务专图 | 路标改变有收益/代价；目标窗口实测 |
| P2 | 扩展 200 图与双平台重导出 | 逐图设计卡、运行记录和画面验收齐全 |

本轮研究未修改运行规则。测量报告里的失败保留为重做基线，不能用旧版通关率或测试条数覆盖。
