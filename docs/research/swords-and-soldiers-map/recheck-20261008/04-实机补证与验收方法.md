# 实机补证与验收方法

这份清单区分原作需要补测的事实、本作需要验收的行为，以及本轮已经执行的测量。研究日期 2026-10-08；本轮未在本机启动原作，没有逐关视频时码或原作数值测量。

## 1. 原作 PC HD 补证

| 问题 | 应取证的画面与操作 | 必须保留的结果 |
| --- | --- | --- |
| PC 分岔与路标 | 完整地图、路标操作、两批部队先后抵达 | 可操作者、影响单位、切换生效时机、汇流点 |
| 工人和矿点 | 同关同速度下从 1 个工人逐步增加，连续多轮往返 | 回款时间、载金、采集/等待、矿点耗尽与分配规则 |
| 坡面与移速 | 同种单位在平地和坡面走可比路段，记录游戏速度 | 原始画面、路长估计、耗时；无法控制变量则不下结论 |
| 跨路攻击 | 同 X 不同高度，逐项观察近战、远程和范围法术 | 命中是否跨路、对象限制、弹道和实际伤害 |
| 建造与防守 | 施工开始、遭受攻击、完成以及守方支援 | 施工时间、暴露、反制、不同位置实际覆盖 |
| 主任务与成就 | 开局任务屏、失败触发、胜利和成就解锁分别记录 | 关卡主目标、可选条件、版本差异、事件优先级 |
| 小中大地图 | 地图导航、相同招募条件下首次接战与增援 | 全图长度、视窗比例、行军时间和阵营交换结果 |

现有公开来源已经足以纠正地图设计方法；尚未获得的原作数值保持待测。PC、iOS、Wii、PS3 和二代来源分开登记。记录截图时注明科技面板是否打开、是否暂停、游戏速度和平台。

## 2. 本作白盒验收

| 领域 | 必须执行的检查 | 失败信号 |
| --- | --- | --- |
| 运输 | 每个矿点、双方方向，至少 10 次完整往返；同时观察 3 分钟 | 第一次回款后停运、同边回跳、到不了汇流/基地 |
| 容量 | 同时采集人数与分配偏好分开记录；增加工人测边际收入 | UI 把分配数误报为采集数；超容量仍无解释地持续采集 |
| 经济暴露 | 袭击工人/运输线，与相同预算无袭击基线比较 | 工人停止或死亡但收入仍自动增加 |
| 设施 | 比较两个位置的保护对象、施工暴露和反制 | 前后塔位只换名字；位置几乎不改变作用 |
| 分岔 | 两种敌情分别验证主路与绕行的价值，切换前后两批单位 | 总是同一路更优、旧部队跳路、单位停在节点 |
| 阵营与图长 | 小中大、双方阵营互换和左右交换 | 意外方向差异被当成阵营特色，长图无可行反制 |
| 任务 | 指定 ID 死亡、到达、越线、保护、倒计时和结算边界 | 任意同类单位替代目标；结算先后随机 |
| 输入 | 鼠标与触屏的招募、研究、矿点、设施、施法、导航和菜单 | 按钮可见但无状态改变、拖屏误施法、关键点难点中 |
| 表现 | 正常局部镜头检查足点、连续地表、背景层级和特效遮挡 | 工人悬空、远近不可辨、效果盖住路标和目标 |
| 生产选择 | 战前、规则、AI、战役、迁移与 HUD 都检查 3–5 类型 | 只隐藏按钮，AI 或旧存档仍招募多余类型 |

对运输的 10 次和 3 分钟要求均执行；若远路单轮很长则延长测量。经济原始日志至少包含时间、单位 ID、所在边和弧长、任务、矿点、载金、交付量与路由下一步。不能只检查一次收入或程序退出码。

三张首批白盒各自还需两种可行计划的记录：相同预算、明确敌情、实际操作和结局。模拟可以发现行为错误；决策是否容易理解、视觉是否清楚、是否有紧张与反击感，必须通过真正游玩和画面审查。

## 3. 本轮实际完成

已执行 200 份当前地图数据与代码散列审计；使用本机 Windows 原生 Godot，固定种子 137、60 Hz、禁用 AI，执行 36 组经济、10 组单兵路线、3 组双向首次接战，共 49 组研究夹具。它们读取当前 DataStore / BattleSim，直接建立测量对象，不经过生产扣款和排队，不写玩家存档，也不修改游戏规则。

结果：[current-map-audit.json](current-map-audit.json)、[native-probes.json](native-probes.json)。确实测到了左右回款差异、左方外矿端点循环、路线时差和长度对首次接战的影响；这些不是原作数据，也不是人类游玩验收。探针正常退出代表测量完成，其中仍记录了明确失败。

网页正文重读、已有 PC 原作图与 2.0 本作画面复核已经完成。本次新建的临时浏览器标签已关闭；未使用 Docker、WSL、虚拟机或模拟器。
